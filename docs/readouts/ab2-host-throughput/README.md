# Four-AB2 hosted-game throughput

September 11, 2026 UTC, Wintermute. Every seat uses Catanatron's depth-two
AlphaBetaPlayer, standard 10-VP/7-discard rules, no domestic trades, and the
unchanged 20-second search deadline. This compares **AB2 hosted by HexSet via
CatanatronBot** with **AB2 hosted directly by Catanatron**. AB2's hypothetical
search still uses Catanatron under both hosts; this measures the current
integration's games/second, not a port of AB2's search to HexSet primitives.

The versions are HexSet `d450a4e46c121d8ead7682f9a48a7cdbfca953ee` and its
supported Catanatron pin `d3f4ad05bb78d8b2309631d6d3cfa8fcb6fda816`. Both arms
use exactly that same native implementation. This is separate from the
latest-upstream port published as [Catanatron PR #389](https://github.com/bcollazo/catanatron/pull/389).
The immutable runtime is the same Python 3.12.14 image used in the preceding
measurements, with PYTHONHASHSEED=0 and BLAS/OpenMP thread limits set to one.

## One worker, one CPU

Eight seeds (680100000..680100007), each played under both hosts with speedups
off and fast: 32 complete game plays. Every arm has a fresh interpreter;
arm order rotates by seed. The initial board, seating, deck and setup position
are generated by the same seeded native constructor. The HexSet arm translates
that initial position, then plays entirely through HexSet's arena and real-game
rules, asking the adapter for every AB2 move.

| Host | Speedups | Games/second | Seconds/game |
| --- | --- | ---: | ---: |
| HexSet | off | 0.0636 | 15.716 |
| Catanatron | off | 0.0569 | 17.580 |
| HexSet | fast | 0.2076 | 4.817 |
| Catanatron | fast | 0.1928 | 5.187 |

In this small sample HexSet-hosted throughput is 7.7% higher with fast enabled
and 11.9% higher with speedups off. The hosts can play different subsequent
games because their turn/RNG semantics and action filtering differ; the table
is an observed hosted-workload result, not an isolated engine speed multiplier.
No significance or universal advantage is asserted.

All 16 within-host off/fast pairs match the complete chosen-action digest,
winner, all-seat VP, turn count and action count. Cross-host action/outcome
identity is not expected. All games reached a winner. Timings exclude common
initial-position construction/translation and interpreter startup; they include
all per-decision adapter reconstruction/search. HexSet's chosen actions are
recorded by a lightweight wrapper inside the timed loop.

## Thirty workers, fast enabled

Each host plays 120 games on the same predetermined board seeds
680200000..680200119, using one dynamic task per game and a 30-worker pool
bounded to 30 CPUs. The two host trials run serially in the order Catanatron,
then HexSet. Every game reached a winner. These batch times include pool
startup, all initial-position construction/translation, per-decision adapter
work and pool shutdown. This is one batch per host, without repeat-order
balancing; results are an operational sample rather than a significance test.

| Host | Games | Batch seconds | Games/second | Mean turns | Mean actions |
| --- | ---: | ---: | ---: | ---: | ---: |
| hexset | 120 | 73.511 | 1.632 | 78.5 | 304.2 |
| catanatron | 120 | 64.900 | 1.849 | 84.2 | 303.0 |

HexSet-hosted throughput is 11.7% lower in this larger
sample. The small serial sample favored HexSet, so it should not be generalized
into a host-speed advantage. The practical 30-worker result is **1.63 games/s in
HexSet versus 1.85 games/s directly in Catanatron** for the current AB2 integration.
This is the same AB2 implementation/settings hosted in two engines, with
independently evolving game trajectories; it does not measure identical
state-transition sequences or separate adapter cost from game-length/search
work differences.

## Reproduce

Export the measured HexSet source into `/study/src` and copy `worker.py`,
`run_serial.py` and `run_pool.py` into `/study`. Use the pinned native package
and environment above. With a writable `/out` and one CPU:

```sh
PYTHONPATH=/study/src python /study/run_serial.py
```

After it finishes, use 30 CPUs for the practical pool measurement:

```sh
PYTHONPATH=/study/src python /study/run_pool.py
```

The scripts use predetermined disjoint seed ranges, reject existing serial
child output paths, fail if a game does not reach a winner, and record per-game
results. Serial summaries include both engine source fingerprints. Runtime
receipts retain image, mounts, selected environment, CPU limit and exit state.
